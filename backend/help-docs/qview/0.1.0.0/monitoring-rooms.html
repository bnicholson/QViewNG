Once your Rooms are connected, the Server Monitor lets you watch every Room from one screen and catch problems before they reach the stats: a Room that has stopped checking in, a Game whose data didn’t all arrive, or a QuizMachine whose send queue is stuck. This article is for the Tournament’s owner and admins on tournament day.

Before you start: you need to be the Tournament’s owner or one of its admins to see Server Monitor. Resending and clearing also need permission to update Games, which Tournament Managers and Tournament Admins have.

Opening the Server Monitor

  1. Open the Tournament and click Server Monitor in the sidebar.

Each Room appears once its QuizMachine has checked in. The page updates by itself: a green Live means changes appear as soon as QView receives them. Reconnecting… or Refreshing every 30s means the live connection dropped, and the page is still updating, just more slowly.

What does each column mean?

  • Check In: when the Room last checked in with QView. A healthy Room checks in regularly.
  • Room, Round: the Room and the Round it’s on.
  • Question: the question the Room says it’s on. If QView hasn’t received all of the Room’s events yet, a second line shows how far QView has actually scored (for example, “Scored through Q7”).
  • QMVersion: the Room’s QuizMachine version.
  • Pending: how many events are waiting in the Room’s QuizMachine to be sent. It should stay at or near 0.
  • Quarantine: events QView received but didn’t apply (see below).
  • Status-Error: what’s wrong, if anything.
  • Resend: asks the Room to send a Game’s events again.

When is a row red?

A row turns red when its Status-Error column shows one of these:

  • Room not communicating?? Late?? The Game is in progress but the Room hasn’t checked in for more than 2 minutes. Go to the Room: the computer may have lost its internet connection, gone to sleep, or QuizMachine may have been closed.
  • Data Incomplete. Resend Advised. QView is missing some of the Game’s events (a question or an event in the middle is missing). Use Resend.

A Room can have more than one row. Besides its current Game, it gets an extra row for any earlier Game with missing data, so you can resend that too. The extra row disappears once that Game’s data is complete.

Resending a Game’s events

  1. Find the red row with Data Incomplete. Resend Advised.
  2. Click Resend on that row.
  3. Wait for the Room’s next check-in. The note under the button tracks progress.

QView can’t reach into the Room directly. Instead, it hands the request to QuizMachine the next time the Room checks in, and QuizMachine sends the whole Game again. The note tells you where it’s at:

  • Requested — awaiting next ping: the Room hasn’t checked in since you clicked.
  • Resend request received by room.: the Room has the request and is resending.
  • Room failed to resend game events. Please issue another resend request.: it’s been more than 30 seconds and the data is still incomplete. Click Resend again.

How can you tell it worked? The note disappears, the row is no longer red, and an extra row for an earlier Game drops off the monitor. The Resend button greys out once the data is complete.

If Resend keeps failing, check that the Room is still checking in (look at Check In). A Room that isn’t online can’t pick up the request. If it can’t get online, export the Game from QuizMachine and import it instead (see Importing Games from an offline Room).

What if a Room’s Pending number is stuck?

Sometimes one event gets refused every time QuizMachine sends it, and everything queued behind it waits. When a Room’s Pending hasn’t gone down for 90 seconds, QView shows a red Clear Pending + Resend? button in that cell. (Users without permission see Stuck instead.)

  1. Click Clear Pending + Resend?.
  2. Read the dialog, then click Clear Pending + Resend.
  3. Leave the Room’s QuizMachine running and connected, and watch the chip in the Pending cell.

Here’s what happens:

  1. Clearing… For up to 5 minutes, QView tells the Room each event arrived but doesn’t apply it, so the Room’s queue empties. Every one of those events is kept in the Room’s Quarantine. Nothing is deleted.
  2. Resending… Once the Room reports nothing pending, QView asks it to resend every affected Game in full, once a minute for up to 10 minutes.
  3. It finishes as one of:
    • Recovered (green): every set-aside event came back and was stored. You’re done.
    • Resend not confirmed (red): the Room didn’t resend everything within 10 minutes. Check the Room is online, then click Resend on any row still marked Data Incomplete.
    • Expired: the 5 minutes ran out with nothing set aside, so nothing changed.
    • Cancelled: you stopped it before anything was set aside.

The final chip stays on the row for 15 minutes.

While a Room is being cleared and resent, its scores in Games in Progress and Server Stats may be behind. Wait for Recovered before you rely on that Room’s stats.

You can stop it with Cancel next to the Clearing… chip. Anything already set aside will still be asked for. Once it’s on Resending…, it can’t be cancelled.

What is Quarantine?

Quarantine holds events QView told the Room it received, so the Room could keep sending, but didn’t apply. Click the shield icon in a Room’s Quarantine column to see them. An amber shield with a number means there are some; a grey shield means none.

  • Set aside while clearing: held during a Clear Pending + Resend. These come back on their own when the Room resends.
  • Rejected: QView couldn’t use the event, and the Reason column says why (for example, the Game no longer exists in QView). Use the copy icon to copy the event exactly as the Room sent it, if you need to pass it to a QView administrator.

The Quarantine count is a history: it doesn’t go down when set-aside events are recovered. Use the row’s Status-Error and Resend columns, not the Quarantine count, to tell whether a Game’s data is complete.

Watching scores live

To watch the Games themselves, click LIVE Stats in the Tournament sidebar. Its Games in Progress tab shows every Room that has checked in within the last 30 minutes, with each Team’s score, and anyone can view it. See Computing Stats for the Team Stats tab.
